# 代码与开发红线

本文是项目开发规范，与 [REQUIREMENTS.md](REQUIREMENTS.md) 同等强制。PR 不符合本文时不得合并。

## 1. 代码质量

- 代码是负债，功能是价值。禁止垃圾、临时、遗留、废弃、重复代码进入仓库。
- 在可读、可扩展、健壮的前提下尽量精简；不为少写几行牺牲结构，也不为抽象而抽象。
- 注释必须中英双语、单行，只解释设计意图、边界、复杂逻辑或非显而易见的行为；禁止复述代码。
- 单个函数不超过 50 行、参数不超过 5 个；超过时用语义清晰的 dataclass 聚合参数，不得硬塞。
- 异常必须捕获具体类型；禁止裸 `except Exception`。跨边界转换异常时保留 `from exc`。
- 无死代码、无重复实现；公共工具只保留一份（例如文件哈希统一走 `hashing.file_sha256`）。

### Python 风格

- Tab 缩进、单引号、行宽 ≤ 120。
- 方法/类之间保留 1 个空行；导入按标准库、第三方、本地分组。
- 变量/函数 `lower_snake_case`，类 `PascalCase`，常量 `UPPER_CASE`，私有成员单下划线。
- 优先 f-string；布尔判断写 `if items:`，不写 `if len(items) > 0`。
- 注释格式 `"""Concise English. 简洁中文。"""` 或单行 `# English. 中文。`。

## 2. 失败策略

- 配置错误、运行错误、资源缺失、插件/扩展缺失或加载失败，一律直接报错，禁止兜底、降级、静默跳过或强行继续。
- 引擎不为宿主错误买单；不兼容错误写法、不自动修正非法输入。宿主误用就崩溃或报错。
- 允许显式、用户可见、语义清晰的策略：用户配置的模型、明确的检索排序/召回策略、并发锁重试（有超时与明确错误）。
  这些策略不得掩盖配置错误或致命运行错误。
- 唯一允许的“单文件失败隔离”是解析失败：`ParseError` 记入失败清单并继续整库同步（需求 FR-206），
  其它 I/O、数据库、模型、配置错误直接上抛。
- 发现 bug 先复现确认；修复必须补测试，覆盖复现路径与修复后的正确行为。

## 3. 模块边界

- 宿主 / 引擎 / 插件 / Agent YAML 职责不得混用。
- 引擎向宿主索取资源，通过明确的实例入口注入；不伪造资源，不在缺失时偷偷替换实现。
- 插件只做能力增强，不吸收宿主资源管理、模型配置、持久化基础设施。
- Agent YAML 只声明配置参数，不承载运行期对象或字符串路径伪装的资源。
- 官方预设插件保持轻量，不内置网络请求、模型 key 管理或外部服务客户端。

## 4. 本项目中的具体解释

- `KnowledgeBase` 是引擎入口；`cli.py` / `mcp_server.py` 只做参数解析与输出格式化。
- 模型目录、索引目录、知识库根目录都来自显式配置；缺失即抛 `WenSuoRuntimeError`，不自动下载、不换模型。
- MCP 工具错误按需求以 JSON 错误对象返回（FR-1013），不吞掉错误。
- MCP `search` 的 9 个参数由需求 FR-1012 固定，是本规范“参数 ≤ 5”的唯一例外，新增参数前先改需求。
- Docling 解析缓存损坏、索引结构版本不兼容都直接报错，并提示明确的修复动作。

## 5. 校验

```bash
uv sync --dev --extra mcp
uv run pytest
uv run ruff check .
```

CI 在 Linux / macOS / Windows 与 Python 3.11–3.13 上执行上述检查。
